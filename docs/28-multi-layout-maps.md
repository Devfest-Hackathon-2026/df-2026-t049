# 第四轮：主竞技场与小时联赛多布局地图

## 实现与数据边界

共享 `web/map-geometry.js` 的 createMapLayout / createGeometry，`web/map-renderer.js` 绘制道路、设施、车辆、河流与事件。没有引入依赖、收费地图或第三方素材。没有修改 Python、Bot、评分、联赛数据库规则、云部署或 Scheduler。

两页均提供城市、沿河、山区 3 种环境，每种 3 套视觉布局。主竞技场手动选择环境和 A/B/C；联赛自动选择，使用 league_hour（旧记录降级到场景/seed）及排序后的真实道路 ID 和端点生成稳定标识。排除 Bot、分数、语言、时间轴位置，刷新后再次观战保持一致。不是每小时强制轮换；相邻小时可能选中同一视觉模板，但真实连接仍按各轮数据绘制。

城市布局采用分区、错位街区和正交圆角道路；沿河布局包括纵向、横向、斜向河带及两岸设施；山区采用不同山谷方向、错落设施、等高线、树林和弯曲道路。主竞技场选用宽间隔的四个位置；联赛使用七个位置。仓库没有额外增设，也不固定在中央。

道路路径仅连接真实 from/to，避让无关设施建筑，并对已用走廊增加代价以减少重叠。曲线采样与按弧长计算的车辆轨迹完全共用。道路长度不改变 travel_turns 或计分。桥面从既有路段与河带的交集生成，仅为显示，不代表后端新增桥梁。

布局与路径缓存有上限，回放不重复运行布局算法。visual-v1 是当前表示版本，后续版本迁移需保留旧布局以保证跨版本视觉复现。额外节点的网格降级不是本轮高质量九布局验收范围；目前重点覆盖 4 节点和 7 节点。

## 回放与交互

- 保留共享回放时钟、暂停小数位置、恢复、倍速、前后单步、重置与时间轴跳转。
- 当前事件摘要来自当前快照：封路、拥堵和本回合需求增长；回退重新构建，不保留未来效果。
- 封路路障、拥堵符号、需求增长边框与数字、配送提示均来自真实记录。没有新增洪水/地震/滑坡事实。
- 道路可悬停或键盘聚焦查看 ID、连接端点和状态。几何交叉不是额外节点，复杂联赛仍可能出现视觉交叉；不宣称已实现真实立交元数据。
- 五辆停靠车采用两排编号；运动中的标签错层。较密集的同步车辆仍可能局部遮挡，需要结合详情读取，未改变真实车辆位置和出发时间。
- 联赛显示环境、布局编号、UTC 场次及道路数，点击观战自动定位回放。
- 两页默认显示完整地图。桌面隐藏显示模式控件，手机提供“查看全图／放大查看细节”分段按钮；细节只在地图容器内横向滚动，不改变布局、车辆位置或回放时钟。
- 简体中文、日本語、English 使用原有翻译机制。

## 第四轮最终收尾（2026-11-09）

### 默认语言与真实编号

首次访问无有效已保存偏好时固定使用日本語，不再匹配浏览器语言。沿用同源 localStorage 键 reliefroute.language，手动选择优先，刷新及跨页保持。存储读写失败时使用日语默认值，并允许本页内存切换；无法承诺跨页保存。不同域名/端口本来就是独立存储范围。

两页地图、车辆目的地、设施详情、事件和无障碍名称统一使用记录中的 D1、S1～S6、R1 等真实 ID。没有改动后端 ID 或记录。地图标题只显示 ID，详情描述使用三语“避難所 S1／避难所 S1／Shelter S1”。不再使用青叶、中央、东丘等虚构地名。

### 地图可读性与交互

普通道路默认不堆叠显示 ID 和耗时；封路、拥堵、车辆、设施需求仍可见。点击道路显示端点、当前通行状态和耗时，并突出路段。层叠边线、轻微路面色差和非路口说明共同区分几何交叉，不添加真实交叉节点。山区只在较长段保留缓和弯曲，短段不反复摆动；桥梁增加沿实际跨河段的护栏和端柱，不增加通行边。

点击车辆或其独立编号底板显示状态、货量、真实目的地、当前道路和 edge.remaining 记录值。返回中的车显示真实仓库 ID，不再沿用上次配送目标。重叠时也可从现有车辆列表选择。点击设施显示总需求、已配送与缺口。键盘 Enter/空格可选择，并恢复选择后的焦点。

历史事件按钮突出对应道路/避难所，**不改变当前回放回合**。事件文字保留发生回合，详情明确标注当前回合与当前状态。已结束事件不会重新激活；时间轴倒退后仍从该回合快照重建。没有添加洪水、地震或滑坡原因。

联赛保持请求序号防止较旧响应覆盖新观战选择。当前 Bot、轮次、环境与地图控制沿用既有区域。下一轮、当前轮、回放轮和部署成功时间统一由真实时间戳经 Intl.DateTimeFormat 转换，明确同时显示 JST 和 UTC，并包含日期以解释跨日。与浏览器所在时区无关。
