# 10 — 测试与演示验收清单（v0.1）

## 引擎单元测试

- [ ] 仓库库存不会为负数；车辆物资不超过其容量。
- [ ] 一个车同一回合不可重复派遣；在途中不可再次派遣。
- [ ] 封闭道路不可新进入；已在路段上的车按规则到下一节点后绕路。
- [ ] 拥堵倍率改变移动回合；值为整数且可复现。
- [ ] 新增需求事件只在指定回合出现，之前无法被 Bot 观察。
- [ ] 避难所收到的有效物资不超过累计需求；超额不能刷分。
- [ ] 车辆卡住时记录原因，不产生无限循环。
- [ ] 24 回合结束时能按约定正确结算在途货物（建议只算已送达量）。

## Bot 协议测试

- [ ] 空数组、错误 JSON、字符串数量、负数、过量、未知车辆、无效目的地均安全拒绝。
- [ ] 同一回合多个合法派车请求不会超过同一仓库总库存。
- [ ] `Nearest First` 和 `Urgency First` 使用相同接口、没有隐藏权限。
- [ ] 无代码配置生成的动作符合同一协议。
- [ ] 外部 Bot 超时不拖垮比赛（若实现）。

## 评分验证

- [ ] 没有配送时 C/T/F 均为 0，E 也为 0，总分 0。
- [ ] 需求全部准时满足且运输有效率时 C/T/F = 1，E 依成本计算，总分不一定满 100。
- [ ] 所有指标被限制在 [0,1]，总分限制在 [0,100]。
- [ ] 相同 `seed + 规则版本 + Bot` 的多次运行日志及分数相同。
- [ ] 事先生成的外部事件与 Bot 调用顺序无关。
- [ ] 随场景版本或权重变化，历史比赛有版本标记，不误混排行。

## 前端与部署

- [ ] 演示能完成：选场景→选 Bot→运行→观看回放→看到完整分项成绩。
- [ ] 地图显示的虚构数据有显著 `SIMULATED` 标识。
- [ ] 道路封闭、需求增加能从动画及日志看出来。
- [ ] 桌面与移动页面不发生关键按钮遮挡。
- [ ] Cloud Run 后端在正式可访问 URL 上能完成比赛。
- [ ] 不需要开发者本机服务，评委能直接观看 Demo。
- [ ] API Key 不出现在 GitHub 和录屏的控制台输出中。

## Pitch 验收

- [ ] 说明目标用户、问题假设和与现有教学游戏的差异。
- [ ] 解释四项指标为何这么定义，并承认简化模拟的局限。
- [ ] 展示相同 seed 下不同策略的真实结果和复现记录。
- [ ] 说明为何选择 Cloud Run / Firebase；为何不让 LLM 裁判。
- [ ] 提交视频、说明书、架构图、素材使用清单；根据官方指南设置公开查看权限。
