## 团队分工建议（3～4 人）

- A：Simulation + 数据模型 + 测试。
- B：Bot Adapter + 裁判 + Scoring。
- C：前端场景展示 + 回放 + 无代码 Bot 表单。
- D（若有）：Cloud Run/Firebase 部署、联调、文档、Demo/Pitch。

具体角色应按真实队伍能力调整；尤其后端状态模型与前端事件接口必须由全员统一。

## 每日集成原则

- 先在纯命令行跑通引擎，再做前端。
- 每天固定回归测试种子与基线 Bot，避免最后一天改评分造成全体失效。
- 每日保留一个稳定可演示版本；UI 可粗糙，裁判不能不可靠。
- 先用固定假数据打通 API，减少前后端互相等待。

## 优先砍掉的功能

1. Gemini；2. 任意外部 Bot 接入；3. Firestore；4. Google Maps；5. 高级动画。

## 需要提交的材料（依据 kickoff，最终核对 Discord）

- 主办方指定 GitHub 仓库中的最终成果。
- 使用官方模板的产品说明、架构图及著作物使用清单。
- 线上组：含 Demo 的演讲视频；线下组：按要求提交 Demo 与 Pitch Slides。
- Google Drive 文件夹的可查看权限和提交表单。
- 留意官方限制及截止时间，以最新正式消息优先。
