# 前后端协作需求：2D 地图与灾害回放

## 当前实现与边界

小时联赛已支持按 UTC 小时确定性生成 7 节点、11 道路、6 避难所、5 辆车和 48 回合的路网。共享前端现可按实际节点连接自动布局，但这不是地理坐标或三种灾害城市。

基础场景为 4 节点、3 条道路；事件场景为相同 4 节点、5 条道路。seed 改变事件时刻、受影响道路和需求位置，不改变地图拓扑。前端坐标不是 GPS，距离不参与计分。

第四轮已在主竞技场和小时联赛共同实现城市、沿河、山镇三种视觉环境，每种 3 套，共 9 套确定性视觉布局。主竞技场可手动选择；联赛按 league_hour 与排序后的真实道路连接选择，不使用 Bot ID、分数或浏览器随机数。仓库位置不固定居中，设施数量未改变。它们改变建筑、植被、地形装饰和道路曲线，不改变可通行连接、权重、Bot 或评分，不等于三种真实灾害场景。环境选择器明确标注此区别。人形图标是需求压力示意，不是灾民人数；拥堵小车是状态符号，不参与引擎。

## 必须修改（仅在实现相应新能力时）

| 功能 | 缺少数据 | 建议可选结构 | 后端职责 | 前端表现 |
| --- | --- | --- | --- | --- |
| 真正不同城市布局 | 地图标识、节点坐标、道路几何 | 顶层 `map: {id, version, nodes:[{id,x,y}], roads:[{id,points:[[x,y],...],level}]}` | 创建连通图、校验 ID、固定版本，保持 seed 可复现 | 按坐标及道路折线绘制；缺失时使用确定性自动布局 |
| 洪水、地震、滑坡等原因动画 | 事件只有通用类型，没有灾害原因 | `payload.cause`, `severity`, `affected_road_ids`, 可选 `area` | 原因必须与真实关闭或耗时变化绑定，生成事件开始与解除记录 | 有明确 cause 才显示积水、裂缝或落石；缺失时显示通用路障 |
| 新避难所 | 动态设施创建规则、坐标、需求批次 | 节点/设施生命周期事件及完整快照 | 定义启用时刻、Bot 可见性、评分分母 | 随快照增加设施，不能只添加地图图标 |

新增结构应为可选字段，原有 API 路径和必填字段保持不变。需要变更协议版本或计分规则时，先团队讨论并记录 ADR。

## 建议修改

| 功能 | 建议字段 | 用途及影响 |
| --- | --- | --- |
| 更精确的运动 | `vehicle.edge.total_turns`, `entered_turn`，或每回合 `traversals:[{vehicle_id,road_id,from,to,start_progress,end_progress}]` | 当前前端从 edge.remaining 和历史快照推导锁定耗时；明确字段可支持未来更复杂路网，无需复制寻路算法 |
| 多层交叉道路 | `road.level`、路口节点 ID | 区分立交与真正可转向路口，避免几何交叉被误读为连通 |
| 初始拥堵 | `base_travel_turns`、`congestion_multiplier` | 当前受控场景以首帧路段耗时为基准；初始已有拥堵时需要显式基准 |
| 人数展示 | `shelter.people_count`，含明确单位与定义 | 不能从物资 amount 推测实际人数 |

## 后续扩展筛选

- 优先：桥梁关闭、落石、倒树、余震。可作为真实封路事件的 cause，视觉成本适中；后端需定义影响与恢复。
- 次优先：暴雨、冰雪运输延误。可映射已有拥堵/耗时机制，但需明确原因和持续时段。
- 已可派生：库存紧张、需求缺口、逾期、配送后的需求缓解。使用当前快照即可，不创建新事件规则。
- 暂缓：火灾蔓延、建筑倒塌、新避难所、补给到达、车辆故障。涉及新实体状态、库存守恒、可用车辆或评分基准；开发成本及回归风险较高。

## 当前回放约定

整数回合是引擎移动、配送和调度完成后的权威快照。相邻快照之间只插值同一次实际路段的进度；每次推进最多走一条路段。需求、事件日志和配送提示在整数边界更新，未来事件不提前显示。播放暂停保留小数进度；拖动时间轴定位整数快照并重建所有状态。

已进入关闭道路的车辆继续完成该路段，这是当前后端规则；不应由前端强制停车。卸货是瞬时结算，前端显示当回合送达提示，不新增卸货耗时。

## 验收与协作

第四轮在 feature/multi-layout-maps 上检查，不修改 Python 核心。运行 `python -m unittest discover -s tests -q`、`node tests/frontend_replay.cjs`、`node tests/league_geometry.cjs` 和 `node tests/map_layouts.cjs`。分别覆盖 59 项 Python 测试、44 份主竞技场记录、3 小时的两种 Bot 和九种视觉布局。新增地图接口前继续扩展几何覆盖与未知节点降级策略。

## 第三轮接口结论

现有 road_closed / road_congested 有开始与结束记录，demand_spike 和配送结果可从快照重建，不需要后端重做这些能力。小时联赛已存在不同拓扑，尚缺的是地图空间几何、地图 ID 和环境语义。

- 必须优先（实现精确地理表现前）：可选 map.id/version、节点 x/y、道路 points。保持旧回放字段可读取。
- 建议下一阶段：edge.total_turns / entered_turn 或明确 traversals，避免未来多路段移动规则使历史推导失效；base_travel_turns 明确初始拥堵。
- 后续扩展：cause、severity、affected_road_ids、area 和环境图层；洪水/地震/滑坡原因必须与实际模拟影响绑定。
- 多仓库仍未由当前 API 提供，前端不能自行增设。历史回放仅最新轮完整保存，若需要历史浏览需提供列表和保留策略。
- 前端负责渲染、回放、布局与提示；队友负责路网生成、真实状态及版本兼容，不改评分或 Bot 决策。

建议 API 错误增加可选 `code`、`line`、`column`：当前语法拒绝仅有英文字符串，前端无法可靠定位错误行。应保留原 `error` 字符串以兼容旧版客户端。

第三轮最终修正已实现三套不同显示坐标和道路几何：城市正交、沿河两岸、山区错落。真实连接与运输耗时不变；详情及持久本地启动见 27-local-league-and-map-layouts.md。

## 第四轮协作结论（2026-11-09）

本轮视觉布局不需要后端修改。已直接利用现有动态拓扑、事件开始/结束、需求批次、车辆 edge.remaining 完成两页渲染。真实仓库仍为 1 个；主竞技场 3 个避难所，联赛 6 个，未添加模拟实体。道路桥面仅取真实道路与视觉河带相交的部分，没有桥梁专属规则。

- **必须优先（引入真实地理场景时）**：约定可选 `map.id`、`map.version`、`map.environment`、节点坐标和道路折线格式。后端仍负责真实连接与运输权重。当前前端不会把未知字段自动当作可信几何；协议确认后添加校验和优先适配，并保留无字段旧记录的 visual-v1 降级。不能把 9 套视觉布局宣传为 9 套真实运输规则。
- **建议下一阶段**：`edge.total_turns` / `entered_turn` 或带区间的 traversals；`base_travel_turns`；道路交叉的真实路口 ID 或层级。现在几何交叉有说明、可聚焦查看端点，但复杂联赛交叉仍较密集，不能从交叉处自行寻路。
- **后续扩展**：灾害 `cause`、`severity`、`area` / `affected_road_ids`；持续时间和恢复规则必须由后端生成且与状态变化一致。通用封路不映射成洪水、地震或滑坡。既有 started/ended 事件已经可用，不需要重复开发。

旧记录通过稳定拓扑生成布局；同一小时不同 Bot、语言、刷新和回放位置不参与布局随机源。未来如修改布局算法应保留版本映射，否则旧记录的视觉位置可能改变。当前方案保证本版本内可复现，不改变记录中的模拟结果。

## 第四轮收尾：前端已独立完成

- 默认日语及已保存语言优先；设施统一真实 ID；地图全图/细节分段查看。
- 车辆、道路、设施点击与当前回合检查器；历史事件突出目标而不伪造当前状态。
- 时间戳统一显示 JST 与 UTC，前端自行使用明确时区转换，不需后端新增日本时间字符串。
- 道路几何简化和桥栏只调整显示，现有真实道路、运输时间、评分、联赛数据库均不变。

这些不是后端待办。仍建议提供结构化 map.id/version/坐标/折线、道路层级、edge.total_turns/entered_turn、base_travel_turns；真实地貌和灾害 cause/severity/area 必须与模拟影响绑定后才启用对应表现。保留旧字段与旧回放降级，不需要为前端编号显示修改任何真实 ID。
