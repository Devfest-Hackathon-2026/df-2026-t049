## 課題と対象

限られた救援物資と車両をどう配分するかは、配送量、期限、公平性の間にトレードオフを生みます。初学者や学習会の参加者が、自分の方針を同じ条件で比較して理由を説明できる環境を提案します。課題は現時点の仮説であり、利用者インタビューや学習効果の実証を完了したとは主張しません。

本製品は完全に架空の災害物流シミュレーションです。実際の救援指揮、医療判断、リアルタイム災害情報の提供には使用しません。

## 体験と実装範囲

メインアリーナでは 24 ターンの模擬配送を行います。利用者は配送先の優先順位、積載上限、出発条件を選び、近距離優先・緊急度優先との計 3 戦略を公開 seed 3 個で比較します。総合点だけでなく需要充足 C、期限内配送 T、公平性 F、資源効率 E を表示し、地図と JSON 記録で結果を振り返れます。

時間別リーグでは 6 避難所、5 車両、11 道路、48 ターンのシナリオで Bot を対戦させます。登録した Bot は次の UTC 時間帯から参加します。パラメーター戦略と制限付きコード Bot、管理トークンによる停止・再開、順位ポイントと最新ラウンドのリプレイを実装しています。初期ポイントは 1000、各回の変動は最大 ±16 で、Elo ではありません。

日本語を既定に中文・English を切替できます。九つの地図は 3 環境 × 3 視覚レイアウトであり、九つの異なる物理災害モデルではありません。道路封鎖・渋滞・需要増加の既存規則を表示します。

## 技術選択と再現性

Bot はルール・貪欲的な優先順位と伝統的なグラフアルゴリズムを使います。経路は Dijkstra 型最短経路計算、行動検証と採点は決定的な Python で処理します。同じ seed と戦略の再現性を確認するテストを用意しています。スコアの重みは C/T/F/E = 60/20/15/5、バージョン 0.1 です。小規模な公開シナリオの結果を一般的な優劣とみなしません。

コード Bot は制限付き AST 解釈で、任意 Python 実行・外部ネットワーク・ファイルアクセスはできません。完全な Python サンドボックスではありません。フロントは HTML/CSS/JavaScript と SVG で構成し、画面と API を同一オリジンで提供します。

## Google Cloud の役割

Cloud Run Service がページだけでなく模擬配送と採点 API を実行します。私有 Cloud Storage にリーグの SQLite スナップショットを保存し、Cloud Run Job を Cloud Scheduler から起動する構成です。Cloud Build / Artifact Registry でイメージを構築・保存し、Service と Job で同じ digest を使います。サービスアカウントでアクセス範囲を分離します。

これにより、個人 PC に依存しない公開環境、周期対戦、状態保存、同じ実行環境の再現を目指します。**旧版 Service は公開されていますが、候補版のデプロイと Bucket・Job・Scheduler・IAM の実設定検証は次段階です。** Gemini / Vertex AI は製品の実行経路に使用していません。
