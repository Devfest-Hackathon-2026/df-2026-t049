# 05 — 评分公式与公平竞赛机制（v0.1 拟定）

> 当前已按以下公式实现开发基线 `scoring_version=0.1`，仍未经过正式赛事校准。公开 seed 结果见 `13-events-scoring.md`；公开赛季前仍须确认权重和场景。

## 单场总分：0～100

`Score = 60*C + 20*T + 15*F + 5*E`

其中 `C、T、F、E ∈ [0,1]`。

### C — 需求满足率（60%）

设避难所 `i` 的优先权重 `w_i`（建议 1～3），总需求 `D_i`，最后实际满足需求 `R_i`：

`C = Σ_i w_i * min(R_i, D_i) / Σ_i w_i * D_i`

只统计满足真实已产生需求的有效配送，避免对同一个避难所超额配送刷分。

### T — 准时完成率（20%）

对每个需求批次 `b`，定义数量 `d_b`、所在避难所权重 `w_b` 与截止回合 `due_turn`。按到期时间优先分配有效配送量 `on_time_b`：

`T = Σ_b w_b * on_time_b / Σ_b w_b * d_b`

提前满足已经出现的需求可计入；未来尚未出现的需求不应提前计入。

### F — 公平性（15%）

第一版使用最弱覆盖率：

`F = min_i ( min(R_i,D_i) / D_i )`，仅考虑 `D_i > 0` 的避难所。

优势：避免仅配送离仓库最近的地点；不足：对一个完全不可到达的地点非常敏感，后续可比较分位数覆盖、Jain 公平指数等替代指标。

### E — 资源效率（5%）

设实际燃料/运距代理成本 `U >= 0`，每场景固定参考预算 `B > 0`：

`E = C * clamp(1 - U/B, 0, 1)`

这里让**没有实际满足任何需求的 Bot 不能靠“完全不派车”获得效率奖励**；用 `C` 抑制刷分。`B` 的定义需随场景版本固定；第一版可使用加权行驶回合数作为 `U`，明确它只是燃料的代理指标。

### 特殊情况

- 生成器必须保证总需求 `Σ_i w_i*D_i > 0`，否则场景无效，不纳入排名。
- 可能由于道路完全阻断或库存不足导致理论最高分小于 100；这属于该场景的约束，同场比较仍公平，跨场汇总需评估难度差异。
- 非法响应/超时：该回合不派车并记录错误；异常次数可以展示为旁支指标，是否额外扣分 **待决定**。
- 非确定性 Bot 的对比需要固定版本与请求结果日志；正式排名以记录为准，不能依赖未来复算一定得到同一行动。

## 例子（仅用于校验公式）

- Bot A: `C=.80, T=.70, F=.40, E=.65` → `48 + 14 + 6 + 3.25 = 71.25`。
- Bot B: `C=.77, T=.75, F=.70, E=.55` → `46.2 + 15 + 10.5 + 2.75 = 74.45`。

Bot B 总需求满足率略低，但更均衡和及时，因此总分更高。

## 场景与赛季规则

- 同一场测试所有 Bot 使用相同 `scenario_version + seed`、同一个事件计划。
- 一次公开练习建议 3 个公开 seed；正式评测建议 5～10 个固定但不提前公开的 seed。
- 赛季排名：`RankScore = average(Score over fixed seeds)`；同时显示标准差和分项均值。
- 不能根据 Bot 名称、调用顺序或行动结果消耗会改变未来外部事件的共享随机源。
- 发布赛季前锁定模拟器、种子集合与评分版本；修改重要规则应重开赛季或全员重算。

## 反作弊与基准

- 至少发布两个基线：`Nearest First`（就近优先）、`Urgency First`（紧急度优先）。
- 记录所有 `observation`、`actions`、判定理由及状态哈希，可重播。
- 每回合限制动作数量、严格类型及数值范围；未授权外部 API 禁止访问未来事件/隐藏种子。
- 需要监控策略是否利用评分漏洞，例如只照顾单个避难所或故意让车辆不移动。
- 成绩只代表**该模拟器**中的表现，不得宣传为现实救援效果证明。


## CLI 评分实现边界

开发场景固定预算 `B=72`；`U` 为所有车辆实际移动的回合数，包含返程和未完成配送的移动，阻塞等待不计。计算采用有理数，结果输出六位小数，总分从未舍入分项计算。最终状态中 `created_turn <= 23` 的全部需求都进入分母；尚在途的货物不计配送；截止回合到达计准时。

`python3 -m reliefroute --rescore outputs/match.json` 从完整保存记录重新计算，忽略缓存 score/summary。旧版 0.1-cli 记录没有移动成本和评分版本，不能直接重算，需用保留的无事件夹具重新运行。输入是可信本地引擎记录，不具备外部提交真实性认证。
