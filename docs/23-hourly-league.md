# 時間別リーグ利用ガイド

## 登録から対戦まで

`/league` で名前と戦略を設定し、Bot を登録します。登録時に表示される管理トークンは一度だけ取得できるため私的に保存してください。Bot ID とトークンで停止・再開できます。アカウントやトークンの復旧機能はありません。

新規・再開 Bot は次の UTC 時間帯から参加します。登録ボタンを押してすぐに試合が生成されるわけではありません。ブラウザーを閉じても、定期処理が稼働するサーバーでは後続の試合に参加します。コード変更は新しい Bot として登録し、以前の順位を引き継ぎません。

## シナリオと順位

倉庫 1、避難所 6、車両 5、道路 11、48 ターンで、UTC 時間帯から seed を決めます。同じ時間帯では全 Bot が同じシナリオで競います。九つの地図配置は表示上の違いであり、規則とスコアは変わりません。

初期順位ポイントは 1000。各ラウンドの総合スコアの相対的な勝敗から、最大 ±16 点を加減します。引分け・単独参加は変動なしです。Elo ではありません。API の整数を画面では `rating_scale`（1000）で割ります。試合の総合スコアと累積順位ポイントは別の値です。

## リプレイと保存範囲

最新の完了ラウンドは各 Bot の完全リプレイを保存します。次の結算で古い完全リプレイを消し、結果の要約とポイント変動を保持します。期限切れリプレイは 404 になります。全履歴をブラウザーから再生する機能はありません。

再生画面は計算済み記録です。実車の位置情報や現実の救援活動ではありません。最終スコアと、再生中のターンの状態を区別して表示します。

## ローカル実行

```bash
python -m reliefroute.server
# 別ターミナルで現在の時間帯を一度結算
python scripts/local_league.py --once
```

既定 DB は `outputs/local-league.sqlite3`。変更時は両プロセスに同じ `--db` を指定します。通常起動は定期結算を始めません。継続実行が必要な場合は別プロセスで `python -m reliefroute.league --db outputs/local-league.sqlite3` を実行します。停止期間の過去ラウンドは補完せず現在の時間帯を処理します。

## 運用上の制約

合計 100 Bot の登録制限がありますが、不正な大量登録を防ぐ仕組みではありません。SQLite 直接利用は永続ディスクのあるローカル用です。クラウドでは私有 GCS スナップショットと Job / Scheduler を使用します。旧版の公開 API に既存試合はありますが、候補版の定期実行・IAM・保存検証は次段階です。
