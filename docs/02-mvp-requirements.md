# 02 — MVP 范围、功能优先级与验收标准（v0.1）

> 范围更新：用户随后明确要求实现每小时多人 Bot 联赛。下面的原提交范围作为历史基线；新增授权范围、当前实现和未完成项见 [每小时联赛](23-hourly-league.md)。原 P2 中公开赛季及用户代码托管不再是永久排除项，但任意代码必须独立隔离执行。

## P0：必须可用（提交前）

| 功能 | 最小验收条件 |
| --- | --- |
| 场景生成 | 至少 3 个固定公开 seed；同一 seed 初始数据一致 |
| 模拟引擎 | 车辆、仓库库存、避难所需求、运输过程可以完整推进 24 回合 |
| 突发事件 | 道路封闭、拥堵、需求增加各至少有一个有效测试样例 |
| 统一 Bot 调用 | 两个参考 Bot 走相同的 `observation -> action` 契约 |
| 无代码 Bot | 选择至少 3 个策略参数，生成配置并参与同一场景 |
| 行动验证 | 不允许超容量、负数物资、重复派遣、访问未来事件等 |
| 评分 | 100 分总分及 C/T/F/E 四项；同一记录重算分数相同 |
| 比赛展示 | 能切换 Bot、运行比赛，看到事件、车辆位置、分数和结果 |
| Google 部署 | 后端部署 Cloud Run 或前端 Firebase Hosting；建议两者均部署 |
| 提交材料 | README、架构图、演示视频、使用素材清单、GitHub 仓库 |

## P1：加分，但不能卡住 P0

- Google Maps 自定义覆盖物（可替换 P0 自建二维地图）。
- Firestore 存储参赛者配置/历史成绩。
- 可回放速度控制、分项指标曲线、跨 seed 排行榜。
- 外部 HTTPS Bot API：**仅经管理员审核的固定端点**，通过严格的请求限制接入。
- Gemini：自然语言 → 结构化规则配置，或解释已记录的比赛决策。

## P2：黑客松不做

- 真实灾害道路或拥堵实时同步、真实救灾建议。
- 军队协同、灾民迁移、医院床位、灾种物理仿真。
- 任意源代码上传执行、开放匿名外部 Bot URL。
- 多物资品类、复杂车辆属性、几十公里级地图、动态天气系统。
- 完整账号体系、公开赛季、付费模式、跨区域真实地理数据库。

## 交互页面（最小）

1. **场景页**：地图、仓库、避难所、车辆、当前事件、时间轴。
2. **Bot 页**：参考 Bot 切换；无代码策略选择；策略摘要。
3. **比赛页**：开始/重置/加速，显示行动与结果；不需要真实时间等待。
4. **结果页**：总分、四项指标、每个避难所的满足情况、比赛日志。

## MVP 完成标准

- `Bot A` 与 `Bot B` 在同一个 seed 上有**可解释的策略差异**，分数可能不同。
- 重复运行 3 次，输出的结构化成绩和事件日志一致。
- 输入明显非法动作时引擎不会崩溃，且会记录拒绝原因。
- 通过公开 URL 打开演示页面，核心流程可以跑通。
- 演示不依赖人工临场改数据库或修改输出分数。

## 显式降级路线

若进度落后，依次移除：Gemini → 外部 Bot API → Firestore → Google Maps；最后仍保留**Cloud Run + 确定性引擎 + 两个 Bot + 成绩 + 简化回放**。不移除基线和评分系统。
