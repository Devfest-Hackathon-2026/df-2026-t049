# CLI 固定场景与手算验收

这是虚构物流模拟，不代表真实灾情。初始场景版本为 `0.1-cli`，当前保留为 `0.2-fixture`，固定标识 seed 0；运输时间线不变。

## 初始状态

- 仓库 D1 位于 N0，库存 60。
- V1、V2、V3 均位于 N0，容量各 10，初始为空闲。
- S1/N1、S2/N2、S3/N3 各有 20 单位需求，回合 0 已产生，截止回合均为 6，优先权重均为 1。
- 三条无向路：N0–N1 耗时 1，N0–N2 耗时 2，N0–N3 耗时 3。没有其他道路或自动事件。
- 回合为 0～23。没有全局随机状态、网络请求或墙上时钟参与结果计算。

## 最近优先策略

按车辆 ID 分配空闲车辆。依最短道路耗时、再按避难所 ID 选择目标。把已在配送中的货物视为该目标的预留量，避免重复满足同一需求；本轮新派遣也立即扣减策略内部的剩余库存与未预留需求。装载量为容量、仓库剩余库存、未预留需求三者最小值。

## 可重复性与边界

完整 JSON 按稳定键序列化，不含运行时间戳。三次相同输入的日志和状态哈希必须完全一致。

测试同时验证超额货物返仓、非法动作不修改库存、未来需求不可见、道路内车辆完成当前路段、无法返仓时 blocked 并逐回合重试，以及回合 23 派出但未到达的货物不计配送。

`Engine` 接收内部可信场景夹具，不提供任意场景导入。外部场景 schema 校验仍是后续工作；事件生成和多 seed 场景已独立提供，详见 `13-events-scoring.md`。状态日志供开发者审计；Bot 只接收独立拷贝的公开 observation。
