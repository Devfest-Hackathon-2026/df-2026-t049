# 日语 Demo 演讲稿与录屏顺序

以下为约四分钟的录制草稿，不是已录制视频。官方时长/模板未提供，提交前按对应会场要求调整。所有比赛画面必须来自真实运行，不使用预填假分数。公开部署成功后再录制最终版。

## 0:00–0:35 — 用户与问题

「限られた物資を、どこへ、どの順番で届けるべきでしょうか。近い場所を優先する方針と、期限が迫る場所を優先する方針では、届けられる量も、公平性も変わります。ReliefRoute Arena は、この違いをコードを書かずに比較できる、災害物流を題材にした学習用シミュレーションです。実際の救援活動への助言ではありません。」

画面：实际公开 URL 的日语首页，显示模拟数据提示。

## 0:35–1:20 — 设置与运行

「マイ戦略を選びます。今回は、充足率が最も低い避難所を優先し、最大積載量まで積み、配送可能なら出発する方針です。シードは 22 にします。実行すると、サーバーが同じルールで 24 ターンを計算します。」

操作：我的策略 → fair / full / any → seed 22 → 运行。暂停、单步或拖动，展示真实道路事件与车辆。

「通行止めや渋滞、需要の増加が起こります。Bot は未来のイベントを知らず、今見える情報だけで判断します。画面のスコアは競技全体の結果で、地図は現在の再生ターンの状態です。」

## 1:20–2:10 — 同条件比较

操作：打开策略对照；停留九场表格与三策略均分；展示 seed 22 两行。

「公開シード三つで、二つの基準戦略と比べます。緊急度優先の平均点は約 78.35 点、今回の公平性優先は約 74.58 点です。しかし、総合点だけでは見えない違いがあります。シード 22 では、緊急度優先の公平性は 50%、今回の設定は 75% です。どの指標を重視するかを、自分の方針と結びつけて考えられます。」

注意：分数仅对应当前评分版本；录制前重跑并核对。

## 2:10–2:45 — 可复现与改进

操作：点击 seed 22 自定义记录，确认参数恢复；下载 JSON。可另录 CLI 重算画面，不暴露本机敏感路径或凭据。

「比較表から戻ると、その競技で使った設定が復元されます。記録を保存して再採点できるので、見た目だけの結果ではありません。積載量や出発条件を変え、結果を比較する学習サイクルを作れます。」

## 2:45–3:30 — Google 技术与选择理由

画面：架构图。此段仅在实际云部署成功后使用完成时。

「Cloud Run 上で、シミュレーション、行動の検証、採点を実行します。ブラウザーだけでスコアを作る仕組みではありません。Cloud Build でコンテナーを構築し、同じサービスから Web 画面と API を提供します。採点には LLM を使わず、決定的な Python ロジックを選びました。同じ設定で同じ結果を得て、判断の理由を説明できることを優先したためです。」

## 3:30–4:00 — 限界与下一步

「現在は小さな架空の道路網と公開シード三つによる MVP です。実ユーザーによる学習効果は、これから検証します。まず、自分の意図を方針にして、同じ条件で試し、結果の理由を説明する。この体験を完成させることを目指しました。」

## 录制完成标准

- 全片含介绍、真实操作、Google 技术、取舍和局限；不是只有地图动画。
- 无 API Key、账单详情、私人标签页或个人信息；无需录控制台登录。
- 验证视频文件从头到尾可播放，字幕/语音和画面一致。
- 核对官方规定的时长、分辨率与文件命名；上传到指定 Drive 并确认评委可查看。
