# 03 — 模拟引擎与数据模型（v0.1 草案）

## 模拟世界

- 完全虚构的**有向或无向道路图** `G=(V,E)`：初版可用无向图，允许边有不同通行时间。
- 节点 `V`：普通路口、仓库、避难所。地图位置用于展示，不代表真实位置。
- 边 `E`：`from`, `to`, `travel_turns`, `is_open`, `congestion_multiplier`。
- 首批场景建议：20～30 节点、约 30～50 边、1 仓库、3～5 避难所、3 车、1 种标准物资单位。
- 一个 `turn` 表示虚拟 10 分钟；总共 24 turn。事件由 seed 生成固定计划。

## 实体（建议字段）

| 实体 | 核心字段 | 说明 |
| --- | --- | --- |
| Depot | `id,node_id,stock` | 库存是整数，不能为负 |
| Shelter | `id,node_id,priority` | 累计由不同批次产生的物资需求 |
| DemandBatch | `id,shelter_id,amount,created_turn,due_turn` | 用于计算满足率与准时率 |
| Vehicle | `id,capacity,status,location,cargo,target` | `idle/delivering/returning/blocked` |
| Road | `id,from,to,base_turns,congestion,is_open` | 当前可用网络 |
| Event | `turn,type,payload` | `road_closed/road_congested/demand_spike` |
| Match | `seed,turn,scenario_version,actions,events` | 重放与审计 |

## 第一版的物流抽象

- 每辆车**从唯一仓库出发**。Bot 只负责在车辆空闲时选择避难所与装载量。
- 引擎根据当前路网自动选择最短预计通行时间路径；**第一版比拼的是调度与物资分配，不是自定义寻路算法**。
- 发车时从仓库扣除物资，并检查容量；每条路的移动耗时由边权计算。
- 到达避难所后物资自动卸载，用于抵扣当前已发生、未满足的需求（按 `due_turn` 较早者优先），未被实际需求吸收的物资不计入分数。
- 完成卸载后车辆自动计划返回仓库；抵达后再次成为 `idle`。若无可行路径，进入 `blocked`，每回合尝试重新规划。
- 道路事件在当前回合的**行动前**生效。车辆进入新路段前按当前状态检查；若车辆已经在路段内，则完成当前路段后再计算后续路线。
- 外部行动不能更改仓库库存、道路图、灾民需求或车辆位置。

## 事件定义

1. `road_closed`：某边从指定回合起无法新进入，可在预定义时间恢复。
2. `road_congested`：在指定区间对边的预计通行时间乘以拥堵系数（例如 1.5、2.0），向上取整到回合。
3. `demand_spike`：为某避难所增加一个需求批次，并分配交付截止回合。

事件**不能依赖 Bot 自己消费随机数的顺序**：在比赛开始前由固定 seed 生成完整事件计划，但给 Bot 的观察只暴露已经发生的部分。

## 单回合顺序（拟定）

1. `apply_events(turn)`：更新道路和新增需求。
2. `advance_existing_vehicles()`：推进已发出的车辆，到站结算和返程；需要约定每回合至多进行一次时间推进。
3. `observe()`：构造当前可见状态，过滤未来事件。
4. `bot.decide(observation)`：仅针对本回合空闲车辆返回派车请求。
5. `validate_and_dispatch()`：检查车辆、库存、数量、目的地和是否存在可行路线；不合法则记日志并跳过该请求。
6. `record()`：保存行动、事件与状态摘要，进入下一个回合。

*实现时需统一“车辆什么时候可再次发车”的时间顺序，所有 Bot 必须使用同一种模拟规则。*

## 可重复性

- 所有浮点边权转换成整数移动回合，避免平台差异。
- 固定 `scenario_version + seed`；修改生成器或评分算法必须改变版本号。
- 回放记录 Bot 行动、每回合外部事件、状态哈希及最终得分。
- 相同 Bot、相同 seed、相同版本输出一致（外部非确定性 LLM Bot 除外；正式排名可要求返回动作缓存或版本冻结）。
